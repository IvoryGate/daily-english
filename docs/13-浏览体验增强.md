# 阶段 13：基础功能完善（浏览体验）

> 本阶段落地"浏览体验优先"的四个基础功能：**搜索、难度筛选、排序、分页/加载更多**。

## 背景思考

爬虫三源让文章量级上来了（40+ 篇，还会持续增长），旧列表一次性全量渲染，既没有搜索也扛不住体量。
用户定的方向是"先做基础功能，再逐步做主题网站和用户体系"，本阶段就从**浏览体验**入手：
搜索、难度筛选、排序、加载更多。主题/样式仍保持现状，后续用可切换主题实现。

## 完成内容

- **后端** `GET /api/articles` 新增组合过滤参数：
  - `q`：关键词搜索，`title` / `excerpt` / `content` 三字段 `LIKE` 模糊匹配
  - `difficulty`：按入门/进阶/挑战过滤
  - `source`（已有）、三者可任意组合
- **前端 API 层** `api/articles.ts`：
  - `fetchArticles(query)` 支持 `q`/`difficulty`/`source`/`sort` 查询对象
  - 对**本地文章**（localStorage 里的 self-精读）做同等过滤：搜索标题/摘要/正文/标签、难度、来源
  - 统一**排序**（`latest` 最新 / `longest` 最长 / `shortest` 最短）在合并 server+local 后执行
- **列表页** `ArticleListPage` 重写：
  - 搜索框（带放大镜图标，`useDeferredValue` 防抖，输入即搜）
  - 难度筛选 tabs（全部/入门/进阶/挑战）
  - 来源筛选 tabs（动态生成，带计数，保留）
  - 排序下拉（最新/最长/最短）
  - **加载更多**：每批 10 篇，过滤条件变化自动重置回第一页

## 技术决策及理由

1. **正文搜索放后端**：列表接口不含 `content`，前端拿不到正文，所以 `q` 搜索在后端 `LIKE` 完成；本地文章有 `content`，前端再补一轮过滤，两条路合并。
2. **分页用"前端分批渲染"而非后端分页**：当前量级（几十~几百篇）全量拉取没压力，前端切片渲染实现简单，且本地文章天然兼容；将来量级大了再换后端 `limit/offset`。
3. **排序在合并后统一做**：server 与 local 数据合并后再整体排序，保证顺序一致（而不是 server 排完 local 再拼导致顺序错乱）。
4. **`useDeferredValue` 做搜索防抖**：React 19 内置，输入延迟渲染避免每击键一次请求，比手写 debounce 干净。

## 实际命令

```bash
# 后端搜索/过滤验证
curl "http://localhost:8000/api/articles?q=climate"                 # 搜标题/正文
curl "http://localhost:8000/api/articles?difficulty=advanced"       # 难度过滤
curl "http://localhost:8000/api/articles?q=war&difficulty=advanced" # 组合

# 前端
npm run build && npm run lint
```
