# DailyEnglish 阶段 04：前端框架（路由 + 数据请求）

> 本文档是「阶段 04 前端框架」的详细开发记录，口语化、为博客积累素材。
> 记录真实命令、真实踩坑，不美化。

## 1. 背景：这一步到底要干什么

阶段 03 把 UI 工具链搭好了（Tailwind + shadcn/ui），也画了静态页面。但那时列表→详情是靠 `useState` 手动切的，数据也直接 import 进组件——这都只是"摆样子"。

阶段 04 的目标是把"摆样子"变成"可点开的静态站"：

1. **React Router**：引入真路由，URL 能表达页面（`/` 列表、`/articles/:id` 详情），能前进后退、刷新不丢状态
2. **数据请求封装**：建 `src/api/` + `src/hooks/`，页面组件不再直接碰数据源
3. **mock 数据跑通**：数据层先返回 mock，但接口签名做成异步 Promise，将来联调换真接口时页面代码零改动

## 2. 路由：react-router 8

安装：

```bash
cd frontend
npm install react-router
```

**版本注意**：react-router 7 开始把 `react-router-dom` 合并回了 `react-router` 一个包，所以现在只装 `react-router`，从 `'react-router'` 导入即可，不用再装 `react-router-dom`。2026 年已经是 v8。

路由结构（`src/App.tsx`）：

```tsx
import { BrowserRouter, Route, Routes } from 'react-router'

<BrowserRouter>
  <div className="min-h-screen bg-background">
    <SiteHeader />
    <Routes>
      <Route path="/" element={<ArticleListPage />} />
      <Route path="/articles/:id" element={<ArticleDetailPage />} />
    </Routes>
  </div>
</BrowserRouter>
```

几个决策：

- **SiteHeader 提到 App 布局层**：原来每个页面自己渲染 header，改路由后统一放布局层，页面只管自己的 main 内容，职责更清晰。
- **详情页用 `useParams()` 拿 id**，而不是把文章对象从列表传过来。这样直接访问 `/articles/3`（或刷新）也能正确加载，这才是真路由的意义。
- **返回按钮用 `<Link to="/">` 而不是 `useNavigate(-1)`**：`-1` 依赖浏览历史，用户直接输入 URL 打开详情页时没有历史，点返回会没反应甚至退出。`<Link to="/">` 永远可靠。
- **整卡可点用 `<Link>` 包裹而不是 onClick**：语义化更好，搜索引擎/辅助技术能识别链接，还自带中键新标签打开等浏览器原生行为。
- 用了 `BrowserRouter`（HTML5 history）而不是 `HashRouter`。代价是部署时 Nginx 要配 `try_files` 让所有路径都回落到 `index.html`（阶段 08 处理），这是 SPA 标准做法，不回避。

## 3. 数据请求封装：为换真接口铺路

核心思想：**页面组件只依赖一个"异步返回文章数据"的函数，不知道数据是从哪来的**。

`src/api/articles.ts` —— 现在从 mock 拿，加 300ms 模拟延迟：

```ts
import { mockArticles } from '@/lib/mockArticles'
import type { Article } from '@/types'

const delay = (ms: number) => new Promise((resolve) => setTimeout(resolve, ms))

export async function fetchArticles(): Promise<Article[]> {
  await delay(300)
  return mockArticles
}

export async function fetchArticle(id: number): Promise<Article | undefined> {
  await delay(300)
  return mockArticles.find((article) => article.id === id)
}
```

将来阶段 07 联调，只把这两个函数体换成 `fetch('/api/articles')` 就行，函数签名不变，**所有调用方零改动**。

`src/hooks/useArticles.ts` / `useArticle.ts` —— 封装加载状态和错误处理：

```ts
export function useArticles() {
  const [articles, setArticles] = useState<Article[]>([])
  const [loading, setLoading] = useState(true)
  const [error, setError] = useState<string | null>(null)
  // useEffect + fetchArticles，卸载时 active 标志防 setState
}
```

这里有个 React 老生常谈的坑值得记：**异步请求回来前组件可能已卸载**，直接 `setState` 会告警（React 18+ 虽不崩但不算干净）。用 `let active = true` + cleanup 里置 false，请求回来只在 `active` 时 setState。

## 4. 页面改造

- **ArticleListPage**：改用 `useArticles()`，分别处理 loading（"加载中…"）、error（红色错误文案）、成功（渲染卡片列表）三个状态。
- **ArticleDetailPage**：`useParams()` 拿 id → `useArticle(id)`。加载中显示占位；文章不存在时显示"文章不存在 + 返回列表"按钮——直接访问一个不存在的 id 也能优雅兜底。
- **ArticleCard**：`onSelect` 回调删掉了，换成 `<Link>` 包裹。

mock 阶段永远不会有 error，但 error 分支的 UI 先写好了，联调阶段真接口出错时直接可用，不用返工。

## 6. 踩坑 / 决策记录汇总

| 项 | 说明 |
|---|---|
| 包名变化 | react-router v7+ 合并了 react-router-dom，只装 `react-router` |
| 返回按钮 | 用 `<Link to="/">` 而非 `navigate(-1)`，避免无历史时失效 |
| 整卡可点 | 用 `<Link>` 包裹而非 onClick，语义化更好 |
| 卸载后 setState | 用 `active` 标志在 cleanup 时阻止 |
| BrowserRouter | 部署时需 Nginx `try_files` 回落，阶段 08 处理 |
