# 阶段 20：AI 深度集成（学习助手）

> 用户要求把 AI 能力深度集成进英语学习系统，兜底用 opencode/zen 的免费模型，用户可自带 API key。支持联网搜索、问答、以及调用本站 API 记录笔记等工具。这一阶段实现基本能力 + 分析技术方案。

## 一、技术方案分析

### 关键发现：Zen 免费模型匿名可用

调研发现 **OpenCode Zen 的免费模型是公开匿名的，不需要注册**——这解释了为什么 opencode 安装即用：

- `GET https://opencode.ai/zen/v1/models` 不带 key → 200（模型列表公开）
- `POST .../chat/completions` 不带 key、用 `deepseek-v4-flash-free` → 正常返回对话结果
- 免费模型 7+ 个：`deepseek-v4-flash-free`、`mimo-v2.5-free`、`ling-3.0-flash-free`、`nemotron-3-ultra-free` 等

**结论：默认兜底 = Zen 免费模型（匿名，不占用任何个人 key）。**

### 统一 OpenAI 兼容层

所有模型源走同一个 `chat/completions` 协议，只是 base_url + key + model 不同：

| 模型源 | base_url | key | model |
|---|---|---|---|
| **Zen 免费（默认）** | `https://opencode.ai/zen/v1` | 匿名（可选 `ZEN_API_KEY` 环境变量） | `deepseek-v4-flash-free` |
| **BYOK** | 用户填（OpenAI/DeepSeek/OpenRouter…） | 用户填（存 user 表） | 用户填 |

前端不直接碰模型（避免 CORS + key 泄露），**后端代理**。

## 二、后端实现

```
backend/app/ai/
├── client.py      # OpenAI 兼容客户端（流式+非流式）
├── providers.py   # 模型源解析（zen-free 默认 / byok）
├── tools.py       # 工具定义 + 执行器
└── chat.py        # 工具循环 + SSE 事件流
```

**路由（`api/routes/ai.py`）：**
- `POST /api/ai/chat`：流式对话（SSE），支持注入当前文章上下文，工具循环
- `GET/PUT /api/ai/config`：读写用户 BYOK 配置（key 不回传明文）
- `GET /api/ai/models`：可用模型列表
- `GET/POST/DELETE /api/ai/notes`：笔记 CRUD（关联可选文章）

**工具集（5 个，`tools.py`）：**

| 工具 | 作用 |
|---|---|
| `web_search` | DuckDuckGo Instant Answer 联网搜索 |
| `get_article` | 拉取本站文章正文供分析 |
| `lookup_word` | 复用有道词典查词（中文释义+音标） |
| `get_learning_stats` | 读用户学习统计 |
| `save_note` | 保存学习笔记到用户账号 |

**工具循环**（`chat.py`）：请求 → 模型返回 tool_calls → 执行工具 → 回填结果 → 继续，最多 4 轮。流式时先收 `content` 增量边发边渲染，工具调用在途中触发。

**数据模型**：User 加 `ai_base_url/ai_api_key/ai_model`（BYOK）；新表 `notes`（id/user_id/article_id/content/created_at）。

## 三、前端实现

- **`api/ai.ts`**：fetch 读 SSE 流式客户端（`streamChat`）+ 配置 API
- **`AIChat.tsx`**：右下角悬浮按钮 → 聊天面板（流式渲染 + 工具调用徽章 + 建议问题 + 停止按钮）。通过路由识别当前文章（`/articles/:id`），自动关联。
- **学习页 AI 辅助**：生词本/复习页"AI 讲解"按钮，通过 `CustomEvent('de:ai-ask')` 打开面板并预填带词义上下文的问题。

## 四、踩坑记录

1. **`decode_unicode=True` 中文乱码**：`requests.iter_lines` 流式解码时中文变成 `æ¯`（UTF-8 被按 latin-1 解）。修复：`resp.encoding = "utf-8"`。
2. **Zen free 模型流式先发 `reasoning_content`**：deepseek 推理模式思考过程先到、`content` 后到。前端只渲染 `content`（正式回答），思考过程丢弃，且 max_tokens 要给足（默认 2000）。
3. **`head -c` 截断误判"没内容"**：测试时用 `head -c` 截断流式输出，看起来像空响应。实际是截断问题，完整输出正常。

## 五、验证

- CDP 全流程：悬浮按钮 → 面板 → 建议问题 → 发"查词+存笔记"→ 工具徽章显示 → AI 回答含释义 → 笔记真实入库 → 阅读页关联文章提示
