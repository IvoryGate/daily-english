# DailyEnglish 阶段 06：数据库（SQLAlchemy + SQLite + seed）

> 本文档是「阶段 06 数据库」的详细开发记录，口语化、为博客积累素材。
> 记录真实命令、真实踩坑，不美化。

## 1. 背景：这一步到底要干什么

阶段 05 的后端接口用的是**内存 mock 数据**（`MOCK_ARTICLES` 列表），服务重启数据就没了。阶段 06 把它换成真正的数据库：

1. **SQLAlchemy ORM 模型**：`articles` 表（规划阶段定的字段）
2. **SQLite**：零配置的文件型数据库，部署时把 `.db` 文件放服务器即可，适合小项目
3. **seed 灌库**：把内置语料从代码灌进库，幂等（跑多次不重复）

完成后路由从"读内存列表"变成"查数据库"，接口签名不变，前端无感知。

## 3. SQLAlchemy 2.0 风格模型

用的 SQLAlchemy 2.0 的**新式声明**（`Mapped` + `mapped_column`），比老式 `Column(...)` 写法类型提示更好：

```python
class Article(Base):
    __tablename__ = "articles"

    id: Mapped[int] = mapped_column(Integer, primary_key=True)
    title: Mapped[str] = mapped_column(String(200))
    excerpt: Mapped[str] = mapped_column(Text)
    content: Mapped[str] = mapped_column(Text)
    difficulty: Mapped[str] = mapped_column(String(20))
    tags: Mapped[str] = mapped_column(String(200), default="")
    read_time_minutes: Mapped[int] = mapped_column(Integer, default=2)
    created_at: Mapped[datetime] = mapped_column(DateTime)
```

数据库文件路径用 `Path` 固定到 `backend/data/daily_english.db`，**不管从哪个目录启动都指向同一个库**。`backend/data/` 和 `*.db` 在 .gitignore 里，不会误提交数据文件。

## 4. seed 脚本：把内置语料灌进库

```bash
cd backend
./.venv/bin/python -m app.seed
```

幂等逻辑：库里已有数据就跳过，避免重复灌。**tags 在数据库里存逗号分隔字符串**（规划阶段定过的决策：MVP 不建多对多表），灌库时 `",".join(tags)` 转字符串，查询时再 `split(",")` 转回列表。

## 5. 路由换查库：局部替换

路由从查 `MOCK_ARTICLES` 换成查 SQLAlchemy：

```python
def _to_summary(row: Article) -> ArticleSummary:
    return ArticleSummary(
        ...,
        tags=row.tags.split(",") if row.tags else [],
        created_at=row.created_at,
    )

@router.get("", response_model=list[ArticleSummary])
def list_articles(db: Session = Depends(get_db)) -> list[ArticleSummary]:
    rows = db.scalars(select(Article).order_by(Article.created_at.desc())).all()
    return [_to_summary(row) for row in rows]
```

几个细节：

- **`Depends(get_db)`**：FastAPI 的依赖注入，每个请求自动开/关一个 session，不用手动管理。
- **`get_db` 是生成器**：`yield db` 之后 `finally: db.close()`，请求结束自动归还连接，这是 FastAPI + SQLAlchemy 的标准组合。
- **ORM 转 Schema 的手动转换函数** `_to_summary`/`_to_detail`：因为 ORM 的 `tags` 是字符串、Schema 的 `tags` 是列表，`model_validate` 直接转会类型不匹配，所以写显式转换。这也让排序、格式化的控制点很集中。
- **列表按 `created_at` 倒序**：最新文章排前面，比 id 升序更合理（id 和创建时间基本正相关，但语义上按时间排序更准确）。

## 6. 启动时自动建表灌库

`main.py` 用 FastAPI 的 **lifespan** 钩子，启动时自动跑 `seed()`（建表 + 灌库，幂等），这样"起服务就有数据"，开发体验好：

```python
@asynccontextmanager
async def lifespan(app: FastAPI):
    seed()
    yield
```

## 7. 验证

```bash
# 1. 手动灌库
./.venv/bin/python -m app.seed        # "已灌入 4 篇文章。"
./.venv/bin/python -m app.seed        # 再跑："已存在数据，跳过灌库。"（幂等 ✓）
ls data/                              # daily_english.db 已生成

# 2. 启动服务验证接口
./.venv/bin/uvicorn app.main:app --port 8000
curl http://127.0.0.1:8000/api/articles        # 列表倒序，不含 content
curl http://127.0.0.1:8000/api/articles/1      # 详情含正文，tags 是数组
curl http://127.0.0.1:8000/api/articles/999    # 404
```

全部通过。

## 8. 踩坑记录

| 坑 | 现象 | 解决 |
|---|---|---|
| DateTime 类型不接受字符串 | seed 时 `created_at` 传 ISO 字符串报 TypeError | mock 数据用 `datetime.fromisoformat()` 转成 datetime 对象 |
| WSL 挂载盘启动慢 | uvicorn 启动要 7 秒以上，curl 太早会 502 | 验证前多等几秒；后台进程用 nohup setsid 防误杀 |
| tags 类型不一致 | ORM 是字符串、Schema 是列表 | 写 `_to_summary`/`_to_detail` 显式转换 |
