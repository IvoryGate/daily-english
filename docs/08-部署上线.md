# DailyEnglish 阶段 08：部署上线准备

> 本文档是「阶段 08 部署上线」的详细开发记录，口语化、为博客积累素材。
> 本阶段完成的是**部署配置与发布流程**（不依赖真实服务器）；等服务器就绪后，按本文档执行即可真正上线。

## 1. 背景：MVP 就差临门一脚

阶段 07 联调完成后，整个 MVP 在本地是完整可用的：SQLite → FastAPI → Vite 代理 → React 页面。阶段 08 的目标是把这条链路搬上 Linux + Nginx 服务器，让外网能访问。

但服务器/域名是外部资源，当下还没就绪。所以本阶段先做**不依赖服务器也能完成的部分**：

1. Nginx 配置模板（静态文件 + API 反代 + SPA 回落）
2. systemd 服务文件（uvicorn 后台常驻、崩溃自拉起）
3. 发布脚本（构建 → 打包 → 一条命令产出可上传的部署包）
4. 部署文档（服务器就绪后照做即可）

## 2. 部署架构

```
                         ┌────────────────────────────────┐
 浏览器 ──▶ 域名 ──▶ Nginx (:80)                        │
                         │  /            → frontend/dist   │
                         │  /assets/     → 静态文件+缓存   │
                         │  /api/*       → 反代 127.0.0.1  │
                         └───────────────┬────────────────┘
                                         │ proxy_pass
                                  uvicorn (:8000)  ← systemd 托管
                                         │
                                     SQLite (data/)
```

三个关键点：

- **Nginx 直接服务前端静态文件**，比让 Python 服务静态文件性能好、配置简单。
- **后端只监听 127.0.0.1**，不暴露到公网，所有请求从 Nginx 进，安全边界清晰。
- **`try_files $uri $uri/ /index.html`** 处理 SPA 路由：用户直接访问 `/articles/1` 时，Nginx 找不到这个路径，就回落给 `index.html`，让 React 路由接管。这是阶段 04 用 BrowserRouter 时就预告过的那步。

## 3. deploy/ 目录内容

```
deploy/
├── nginx.conf.example    # Nginx 站点配置模板
├── dailyenglish.service  # systemd 服务单元
└── deploy.sh             # 构建 + 打包发布脚本
```

### nginx.conf.example

`/api/` 反代到本机 uvicorn，`/` 和 `/assets/` 走静态文件。`/assets/` 单独配置 30 天缓存——因为 Vite 构建产物带内容 hash（`index-CtsNHoeX.js`），文件名变了就说明内容变了，可以放心缓存。

### dailyenglish.service

```ini
[Service]
User=www-data
WorkingDirectory=/opt/dailyenglish/backend
ExecStart=/opt/dailyenglish/backend/.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
Restart=always
```

`Restart=always`：后端崩溃自动拉起，配合 `RestartSec=3` 避免频繁重启。用 systemd 而不是 nohup/setsid，进程管理正规化，开机自启、日志（`journalctl -u dailyenglish`）都免费拿到。

### deploy.sh

```bash
./deploy/deploy.sh        # 默认用 git commit 短 hash 命名版本包
./deploy/deploy.sh v1.0   # 或指定版本名
```

产出 `build/release/<tag>.tar.gz`，结构：

```
解压后/
├── backend/    # 后端源码 + requirements.txt（.venv 服务器上另建）
└── frontend/   # 前端构建产物（Nginx 直接服务）
```

**刻意不入包的东西**：`.venv`（每台机器的虚拟环境独立）、`data/`（数据库是运行时数据，绝不覆盖线上数据）、`node_modules`。发布包只含"部署一个版本所需的最少内容"。

## 4. 服务器部署步骤（服务器就绪后执行）

以下命令在**服务器**上执行，按序做完即上线：

```bash
# 1. 基础环境（Ubuntu/Debian 示例）
sudo apt update
sudo apt install -y nginx python3 python3-pip python3-venv

# 2. 解压发布包到部署目录
sudo mkdir -p /opt/dailyenglish
sudo tar -xzf /tmp/<tag>.tar.gz -C /opt/dailyenglish
sudo chown -R www-data:www-data /opt/dailyenglish

# 3. 后端：建虚拟环境 + 装依赖 + 灌数据
cd /opt/dailyenglish/backend
sudo -u www-data python3 -m venv .venv
sudo -u www-data ./.venv/bin/pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
sudo -u www-data ./.venv/bin/python -m app.seed    # 建表 + 灌内置语料

# 4. systemd 托管后端
sudo cp /opt/dailyenglish/backend/app/../deploy/dailyenglish.service /etc/systemd/system/ 2>/dev/null \
  || sudo cp /tmp/dailyenglish.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now dailyenglish
curl http://127.0.0.1:8000/api/health               # 应返回 {"status":"ok"}

# 5. Nginx
sudo cp /opt/dailyenglish/backend/app/../deploy/nginx.conf.example /etc/nginx/sites-available/dailyenglish
# 编辑 server_name 为真实域名
sudo sed -i 's/example.com/你的域名/g' /etc/nginx/sites-available/dailyenglish
sudo ln -s /etc/nginx/sites-available/dailyenglish /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx

# 6. 验证
curl -I http://你的域名/           # 200，SPA 页面
curl http://你的域名/api/health    # {"status":"ok"}
```

> 注：deploy/ 下的 service 和 nginx 模板需要先传到服务器。发布脚本暂未包含它们，真实部署时把整个 `deploy/` 目录一并 scp 过去即可。

## 6. 踩坑/决策记录

| 项 | 说明 |
|---|---|
| tar --exclude 失效 | 该 tar 不认 `--exclude='__pycache__'` 这种写法 → 改用 `find ... -exec rm -rf` 先清理再打包 |
| 发布包不含运行时数据 | data/（数据库）绝不随版本包发布，避免覆盖线上数据 |
| systemd vs nohup | 服务托管用 systemd：开机自启、崩溃自拉起、日志统一 |
| assets 长缓存 | Vite 产物带 hash，文件名=内容，可放心 immutable 缓存 |
