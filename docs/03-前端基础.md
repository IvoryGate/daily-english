# DailyEnglish 阶段 03：前端基础（Tailwind + shadcn/ui + 静态页面）

> 本文档是「阶段 03 前端基础」的详细开发记录，口语化、为博客积累素材。
> 记录真实命令、真实踩坑，不美化。

## 1. 背景：这一步到底要干什么

骨架已经能跑了（阶段 02），但这只是"空壳"。阶段 03 的目标是给前端装上真正的 UI 工具链：

1. **Tailwind CSS v4**：样式方案，Vite 插件方式接入，不用传统 PostCSS 配置
2. **shadcn/ui**：组件库方向（规划阶段定的），选它是因为 Tailwind 原生、代码直接进项目可控，不像 MUI 是黑盒
3. **静态页面骨架**：文章列表页 + 阅读页的版式，用 mock 数据跑起来，不接后端

规划文档里阶段划分很明确：这一阶段**只搭 UI 骨架**，路由、数据请求放到后面阶段。所以页面间的跳转先用 React state 临时切一下，不引入 router，避免过度设计。

## 2. 前端目录结构

按规划文档定了 `frontend/src/` 的目录：

```
src/
├── api/          # API 请求封装（阶段 05 用）
```

顺手把 Vite 模板的演示文件全删了：`App.css`、`assets/`（react.svg、vite.svg、hero.png）、`public/icons.svg` 等。这些是脚手架自带的 demo，留着会干扰后续开发。同时给 `vite.config.ts` 加了 `@/` 路径别名（指向 `src/`）和 `/api` 代理（指向后端 8000 端口，联调时用）。

## 3. Tailwind CSS v4：和 v3 完全不一样的接入方式

Tailwind v4 的最大变化是**从"配置文件驱动"变成"CSS 驱动"**。v3 要在 `tailwind.config.js` 里写 content 扫描路径、主题扩展；v4 直接一个 Vite 插件搞定：

```bash
cd frontend
npm install tailwindcss @tailwindcss/vite
```

```ts
// vite.config.ts
import tailwindcss from '@tailwindcss/vite'

export default defineConfig({
  plugins: [react(), tailwindcss()],
})
```

然后在 CSS 里一行 `@import 'tailwindcss'` 就全量启用了，主题变量用 `@theme` 块定义。编译原理也变了：v3 用 PostCSS + autoprefixer 扫描 class 字符串，v4 基于 Lightning CSS，直接在编译期处理，构建速度更快。

### 坑：ESM 里不能用 `__dirname`

配路径别名时顺手踩了个小坑：项目是 `"type": "module"`，`vite.config.ts` 里 `__dirname` 会直接报错（ESM 没有这个全局变量）。Node 20+ 可以用 `import.meta.dirname` 替代：

```ts
import path from 'node:path'
alias: { '@': path.resolve(import.meta.dirname, './src') }
```

## 4. shadcn/ui：新版 CLI 变化很大

### 初始化

按 shadcn 官网文档初始化。**2026 年的新版 CLI 和老教程完全不一样了**，参数都变了：

```bash
npx shadcn@latest init -y -b radix -t vite -p nova
```

- `-b` 不再是"基础色"，而是**组件底层库**：`radix` / `base` / `aria`（radix 是老牌经典）
- `-t` 指定框架模板：`vite`（会校验你确实是 Vite 项目）
- `-p` 指定视觉预设：`nova`（默认，Lucide 图标 + Geist 字体）
- 颜色迁移到了预设里，初始化时选 preset 就带上了

选 `nova` 预设后，自动装好了 `radix-ui`（统一包）、`lucide-react`、`class-variance-authority`、`tw-animate-css`、`@fontsource-variable/geist` 字体，并生成 `components.json` + 完整的 CSS 主题变量（oklch 颜色、暗色模式、圆角体系）写入 `src/index.css`。

### 添加组件

```bash
npx shadcn@latest add card badge separator --yes
```

### 坑 1：卡死 + 零输出（registry 网络问题）

`add` 命令跑起来完全没输出，超时被杀掉。排查了半天，发现不是卡交互，是 shadcn 内部要用 fetch 去 **npm 官方 registry** 查组件依赖版本，而官方 registry 在国内网络环境基本连不上（curl 测 ui.shadcn.com 是通的，registry.npmjs.org 不通）。解决方案是项目级 `.npmrc` 指向镜像：

```ini
# frontend/.npmrc
registry=https://registry.npmmirror.com
```

加了 `.npmrc` 之后 `add` 秒过。这个文件同时让以后所有 `npm install` 自动走镜像，一劳永逸。

### 坑 2：组件文件被写到了错误的 `@/` 目录

初始化成功后检查文件，发现组件没进 `src/components/ui/`，而是生成了一个字面量目录 `@/components/ui/`。原因：shadcn 解析路径别名时读的是**根 `tsconfig.json`**，而 Vite 模板的根 tsconfig 是 `project references` 结构（`files: []`，实际配置拆在 `tsconfig.app.json`），shadcn 没找到 paths，就回退用字面 `@/`。

修复：把文件从 `@/` 移到 `src/` 对应位置，删掉误生成的 `@/` 目录，并**在根 `tsconfig.json` 也补一份 `paths` 配置**，这样 shadcn 之后 add 组件就会写到正确位置。

### 顺带解决：TS 6.0 弃用 `baseUrl`

配别名时先按老习惯写了 `baseUrl: "."`，TS 6.0 直接报 `TS5101: Option 'baseUrl' is deprecated`。TS 5.0 开始 paths 就可以不依赖 baseUrl，直接相对 tsconfig 文件写 `"./src/*"`，删掉 baseUrl 即可。

## 5. 静态页面骨架

这一阶段的核心产物。数据结构严格对齐规划文档的 `articles` 表字段：

```ts
// src/types/index.ts
export type Difficulty = 'beginner' | 'intermediate' | 'advanced'

export interface Article {
  id: number
  title: string
  excerpt: string
  content: string
  difficulty: Difficulty
  tags: string[]
  readTimeMinutes: number
  createdAt: string
}
```

mock 数据（`src/lib/mockArticles.ts`）放了 4 篇公版 Aesop 寓言（The Tortoise and the Hare、The Boy Who Cried Wolf、The Fox and the Grapes、The North Wind and the Sun），正文是公共领域文本，没有版权问题——正好验证规划阶段定的"内置语料用公版短文"决策。

组件和页面：

- `SiteHeader`：顶部导航，站点名 + 标语
- `ArticleCard`：文章卡片，难度用彩色 Badge（绿=入门/黄=进阶/红=挑战），标签用 outline Badge，右侧阅读时间
- `ArticleListPage`：列表页，标题区 + 卡片纵向列表
- `ArticleDetailPage`：阅读页，返回按钮 + 大标题 + 元信息 + 分隔线 + 正文段落（正文按空行 split 渲染）
- `App.tsx`：用 `useState` 临时做列表/详情切换（阶段 04 换成真路由）

## 6. 验证

```bash
cd frontend
npm run build   # tsc -b && vite build，通过
npm run lint    # oxlint，0 error（只有 2 个来自 shadcn 官方组件的 fast-refresh warning，属正常）
```

`npm run dev` 启动 dev server，`GET /` 返回 200，页面标题正确。**注意 WSL 挂载盘 IO 慢，Vite 冷启动约 10 秒**，curl 要等一会儿再访问。

## 7. 踩坑记录汇总

| 坑 | 现象 | 解决 |
|---|---|---|
| ESM `__dirname` | vite.config.ts 直接报错 | 用 `import.meta.dirname` |
| shadcn add 无输出卡死 | 连不上 npm 官方 registry | 项目 `.npmrc` 指清华镜像 |
| 组件写到 `@/` 目录 | shadcn 没读到子 tsconfig 的别名 | 移动文件 + 根 tsconfig 补 paths |
| TS 6.0 弃用 baseUrl | TS5101 编译错误 | 删 baseUrl，paths 用相对路径 |
| WSL 挂载盘 IO 慢 | Vite 冷启动约 10s | curl 验证前多等几秒 |
