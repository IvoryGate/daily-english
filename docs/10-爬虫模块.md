# 阶段 10：爬虫模块（VOA 内容资源）

> 本阶段为 DailyEnglish 补上"内容资源"：从公有领域的 VOA Learning English 抓取英文文章入库，
> 前端加来源筛选与一键同步。解决此前只有 4 篇 seed + 手动粘贴、缺乏可持续内容来源的问题。

## 背景思考

把 englio.ai 的功能清单逐条对照后，发现"逐词点查、生词本、闪卡"这块我们已经有了，
唯独**内容资源**是空的——竞品有"560+ 精选文章，来自 VOA/BBC/NPR/Guardian 等 10 大来源"。

第一反应是照抄它抓 10 个源。但一查版权就清醒了：

- **VOA（Voice of America）**：美国政府出资制作，**公有领域（public domain）**，公开页面/Feed，抓取转载完全合法，还自带分级（Learning English 有 Level 1/2/3）。
- **BBC / NPR / Guardian / Nat Geo / AP / Sci American**：全部**有版权**，全文抓取有法律风险——这正是我在 AGENTS 里"真实外刊版权绕行"要守的底线。

所以范围砍到**只爬 VOA**。它内容又多又免费又分级，恰好是"阅读练级"最理想的素材。**版权是这次方案最值钱的决策。**

技术路线也和预期不同：本想走 RSS（比较规范），但实测 VOA 的 RSS 端点不稳定（`/z/id/rss` 返回 HTML、`/api/*` 返回 11B 错误 JSON），干脆就用 **HTML 栏目页 + 详情页**抓，反而更贴合"爬虫"两个字。正文容器实测是 `div.wsw`。

## 完成内容

- **后端模型**：`Article` 加 `source`（seed/voa）、`source_url` 两列；用轻量 `migrate()` 幂等补列（SQLite 不支持 `ADD COLUMN IF NOT EXISTS`）
- **爬虫模块** `backend/app/crawler/`：
  - `fetcher.py`：6 个栏目页（American Stories / As It Is / Science & Tech / Health & Lifestyle / Everyday Grammar / Words & Their Stories）→ 提取文章链接 → 详情页 `div.wsw` 取正文，带 UA 头
  - `normalizer.py`：清洗噪音段落（byline/Embed/Also of Interest）、算阅读时长（200词/分）、裁 excerpt
  - `run.py`：`crawl()` 主流程，按 `source_url` 去重幂等，短文（<80 词，多为音频/视频页）自动跳过
- **接口**：`POST /api/crawl/voa` 触发抓取；`GET /api/articles?source=voa` 支持来源过滤；列表 DTO 带 `source/source_url`
- **前端**：`Article.source` 类型改为 `seed | voa | local`；列表页加**来源筛选**（全部/内置/VOA/我的，带计数）+ **同步 VOA 文章**按钮 + 卡片来源徽章

## 技术决策及理由

1. **只爬 VOA（公有领域）**：版权是硬约束，碰有版权源等于给项目埋雷。VOA 全部合法，Go 得安心。
2. **HTML 抓取而非 RSS**：RSS 端点实测不稳定，栏目页 HTML 稳得多；用 `div.wsw` 这个稳定容器抓正文。
3. **难度按栏目映射**：American Stories / Words & Their Stories / Science → `advanced`，As It Is / Health / Grammar → `intermediate`。不花成本做 AI 分级（那是下一个大项，需要 LLM key），先用 VOA 栏目自带的难度粗分。
4. **SQLite 轻量迁移**：项目没上 Alembic（阶段 06 定的简单路线），新列用 `PRAGMA table_info` + `ALTER TABLE` 幂等补齐，启动时 seed() 里执行。
5. **前端三来源统一**：seed（内置）/ voa（爬取）/ local（用户粘贴 localStorage），一套 source 字段驱动筛选 + 徽章 + 详情页删除按钮（仅 local 可删）。

```bash
cd backend && ./.venv/bin/pip install requests beautifulsoup4 -i https://pypi.tuna.tsinghua.edu.cn/simple

./.venv/bin/uvicorn app.main:app --port 8000

curl -X POST http://localhost:8000/api/crawl/voa

curl "http://localhost:8000/api/articles?source=voa"
```

## 踩坑记录

- **音频/视频页没有正文**：VOA 很多文章其实是播客（How to Pronounce 栏目），`div.wsw` 为空或正文很短。解法：`MIN_WORDS=80`，太短的直接跳过不入库。
- **栏目 id 404**：Health & Lifestyle 我从别处猜了个 `z/9455`，实测 404；从首页导航 HTML 里精确取到正确 id `z/955`。
- **WSL 挂载盘 mtime 精度导致 Vite 喂旧代码**：这是本阶段最磨人的坑。`/mnt/f` 跨文件系统 stat 时间戳粒度成问题，Vite 判定"文件没变"就返回缓存的旧模块——于是明明改了代码，浏览器/headless 看到的还是旧页面（筛选按钮消失、正文缺席）。解法：改完代码务必**重启 vite dev 并清 `node_modules/.vite`**，再验证，别信热更新。
- **bash 超时会连带杀掉刚起的后台服务**：组合命令里 `sleep` 太久触发工具超时，把 `nohup setsid uvicorn` 也卷走了。教训：启动命令要短、验证命令单独跑。
