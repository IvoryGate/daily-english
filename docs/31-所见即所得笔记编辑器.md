# 阶段 31：笔记编辑器所见即所得

## 背景思考

阶段 30 做完分屏编辑器（左源码右预览）后，用户问了一句很关键的话：

> 能做成 typora 那种实时渲染的吗？

Typora 的本质不是"预览"，而是**所见即所得**——你看到的编辑区就是最终渲染效果，光标处短暂显示 Markdown 源码符号（如 `**`），失焦后语法符号消失、只剩下格式化文本。分屏模式始终有"源码视角"和"预览视角"之间的割裂感。

方案选型时排除了手写 contenteditable（可控但工作量大、易出 bug），选了 `@mdxeditor/editor`——基于 Lexical 的 React 所见即所得 Markdown 编辑器，兼容 React 19，自带完整工具栏和"编辑/差异/源码"三模式。

## 完成内容

### 1. 安装 `@mdxeditor/editor@4.2.0`

React 19 peer 兼容，无额外 native 依赖。注意这个库的包名经历了 `mdx-editor` → `@mdxeditor/editor` 改名，用新版包名。

### 2. 封装 `NoteEditor` 组件（`frontend/src/components/NoteEditor.tsx`）

核心结构：

```tsx
<MDXEditor
  ref={ref}
  markdown={value}                 // 受控：初始值
  onChange={onChange}              // 每次编辑输出新 markdown
  contentEditableClassName="min-h-64 max-w-none"
  className="mdxeditor rounded-xl"
  placeholder={...}
  plugins={[
    headingsPlugin(), listsPlugin(), quotePlugin(),
    linkPlugin(), linkDialogPlugin(),
    markdownShortcutPlugin(), codeBlockPlugin(),
    toolbarPlugin({ toolbarContents: () => (
      <DiffSourceToggleWrapper>
        <UndoRedo /> <BlockTypeSelect /> <BoldItalicUnderlineToggles />
        <ListsToggle /> <CreateLink /> <InsertCodeBlock />
      </DiffSourceToggleWrapper>
    ) }),
  ]}
/>
```

要点：

- **受控值同步**：`markdown` prop 只在挂载时读一次，外部状态变化需 `ref.current.setMarkdown(value)` 手动同步（`useEffect` 里做，且用 `value !== getMarkdown()` 防循环）。
- **工具栏**：Undo/Redo、Block 类型选择（段落/标题/引用/代码）、粗斜下划线、列表切换（含勾选清单）、链接、代码块。`DiffSourceToggleWrapper` 提供 **Rich text / Diff / Source** 三种视角切换。
- **`suppressContentEditableWarning` 是坑**：v4 的 `MDXEditorProps` 里没有这个属性，加上会直接 TS 类型报错。

### 3. 主题对齐（`frontend/src/index.css`）

mdx-editor 用一组 CSS 变量（`--baseBg/--baseText/--primaryBg/...`）驱动主题，我把它们全部映射到项目 shadcn token：

```css
.mdxeditor {
  --baseBg: var(--card);
  --baseText: var(--foreground);
  --baseTextSubtle: var(--muted-foreground);
  --baseBorder: var(--border);
  --baseButtonBgActive: var(--muted);
  ...
}
```

明暗自动适配：`--card`/`--foreground` 本身就是主题变量，且 v4 用 `.dark` class（项目 `<html class="dark">` 天然对齐，不需要 data-color-mode）。

再补了 `contenteditable` 的排版样式（h1/h2/h3/p/ul/ol/code/pre/blockquote 的字体与间距），保持和正文阅读一致的观感。

### 4. NotesPage 集成

- 删除 `insertAtCursor` / `formatSelection` / 手写工具栏 / Textarea / 预览分屏。
- 编辑态直接用 `<NoteEditor value={editing.content} onChange={...} />`，底部 取消/保存。
- 列表项仍用 react-markdown 渲染（只读展示）。

## 技术决策及理由

1. **选专业库而非手写**：Typora 级交互（语法符号即时显隐、块级转换、选区格式化）实现难度高且边界 bug 多。Lexical 系成熟库把这块做稳了，投入产出比最高。
2. **CSS 变量映射而非引 typography 插件**：项目没装 `@tailwindcss/typography`，而 mdx-editor 已用变量驱动全部视觉，映射到 shadcn token 即获得完整的明暗/风格继承。

## 实际命令

```bash
cd frontend
npm install @mdxeditor/editor --registry=https://registry.npmmirror.com
npm run build
```

## 踩坑记录

1. **`suppressContentEditableWarning` 导致类型报错**：v4 `MDXEditorProps` 无此属性。删掉即可。
2. **v4 明暗判断是 `.dark` class 而非 data-color-mode**：读 `style.css` 才发现的，项目 `html.dark` 恰好匹配，零额外适配。
3. **`Input.insertText` 输入 `## ` 不会自动转 heading**：mdx-editor（Lexical）不是 Typora 的"输入 Markdown 符号即转换"，它靠 `markdownShortcutPlugin` 处理少数语法（如列表 `- `、引用 `>`），标题要靠 BlockTypeSelect 选择或快捷键。这属于交互差异而非 bug——所见即所得能力是完整的。
