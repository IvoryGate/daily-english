# DailyEnglish 阶段 07：前后端联调

> 本文档是「阶段 07 前后端联调」的详细开发记录，口语化、为博客积累素材。
> 记录真实命令、真实踩坑，不美化。

## 1. 背景：这一步到底要干什么

从阶段 03 到 06，前端一直用 mock 数据、后端一直有真接口，两边数据结构对齐好了但**没接上线**。阶段 07 就是那条"临门一脚"的链路：

1. 前端 `src/api/articles.ts` 的两个函数体，从"读 mock"换成"fetch 真接口"
2. 字段映射：后端 snake_case → 前端 camelCase
3. 删掉前端 mock，不再有两套数据源
4. 顺手做阅读体验打磨

Vite 代理在阶段 03 就配好了（`/api` → `127.0.0.1:8000`），所以前端代码里直接 `fetch('/api/articles')`，请求会由 dev server 转发到后端，**没有 CORS 问题**（同源），这也是"前后端彻底分离但开发时无缝衔接"的经典做法。

## 2. API 层改造：函数签名不变，只换实现

阶段 04 的远见在这里兑现了。`fetchArticles` / `fetchArticle` 的**签名完全没动**，页面和 hooks 一行没改：

```ts
export async function fetchArticles(): Promise<Article[]> {
  const data = await request<ArticleSummaryDTO[]>('/api/articles')
  return data.map(toArticle)
}
```

新增了 **DTO 类型**（`ArticleSummaryDTO` / `ArticleDetailDTO`），描述后端 JSON 的真实形状（snake_case），再加 `toArticle` 做字段映射：

```ts
function toArticle(dto: ArticleSummaryDTO): Article {
  return {
    ...,
    readTimeMinutes: dto.read_time_minutes,
    createdAt: dto.created_at,
  }
}
```

这个"DTO + 映射函数"模式的好处：后端字段怎么变都只影响 api 层这一个文件，页面永远用 camelCase 的干净对象。

## 3. 类型诚实化：列表接口没有正文

联调时暴露一个类型设计问题：`Article.content` 原来是必选字段，但**列表接口根本不返回 content**（只有详情返回）。mock 阶段都是全量数据所以没暴露，真接口立刻暴露了。

修复：`content` 改成可选字段 `content?: string`，详情页渲染时 `(article.content ?? '').split(...)` 兜底。类型描述的是"列表数据确实没有 content"这个事实，而不是假装它存在。

## 4. 404 处理

```ts
export async function fetchArticle(id: number): Promise<Article | undefined> {
  const res = await fetch(`/api/articles/${id}`)
  if (res.status === 404) return undefined
  ...
}
```

后端 404 时返回 `undefined`，hooks 里 `article` 变 null，详情页走"文章不存在"兜底 UI——阶段 04 写的分支现在真正跑起来了。

## 5. 体验打磨（阅读方向的小优化）

- **难度 badge 补进详情页**：详情页原来只有阅读时长和标签，现在头部加难度徽章（绿/黄/红），信息完整度对齐列表页。难度映射原来定义在 ArticleCard 里，抽到 `src/lib/difficulty.ts` 两个页面共用，避免复制粘贴。
- **列表 loading 换骨架屏**：原来加载中是"加载中…"文字，换成 3 个 `animate-pulse` 的灰色占位块，观感更好。
- **正文阅读**：`max-w-3xl` + 15px 字号 + 宽松行距（leading-7），保持"舒适阅读"的定位。

## 6. 验证

两个服务都在跑的情况下（前端 5173 / 后端 8000）：

```bash
# 通过 Vite 代理请求后端（同源，无 CORS）
curl http://localhost:5173/api/articles     # 返回数据库真实数据，按创建时间倒序
curl http://localhost:5173/api/articles/1   # 详情含正文
```

浏览器打开 http://localhost:5173：列表显示数据库 4 篇文章（倒序），点进详情正文正常，刷新直接访问 `/articles/1` 也能加载。

```bash
cd frontend && npm run build   # 通过
cd frontend && npm run lint    # 0 error
```
