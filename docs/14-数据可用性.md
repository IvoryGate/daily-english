# 阶段 14：数据可用性（原文外链 + 生词导入导出 + 词典缓存管理）

> 本阶段是"基础功能完善"的收尾，补齐数据可用性三件：阅读原文外链、生词本导入/导出、词典缓存清理。
> 至此基础功能全部完成，接下来进入大工程——用户体系。

## 背景思考

基础功能分三组：浏览体验（阶段 13 上半）、学习记录（阶段 13 下半）、数据可用性（本阶段）。
前两组做完后，还剩三个"数据层面的小痛点"：

1. 爬来的文章有 `source_url`（原文链接）但一直没展示，读了全文想去看原文/出处还得自己找
2. 生词本存在浏览器 localStorage，**清缓存/换电脑就没了**，需要一个备份导出 + 恢复导入
3. 词典点查有缓存（离线可读），但缓存会越积越多，没有清理入口

## 完成内容

- **阅读原文外链**：文章详情页头部加"查看原文"按钮（`ExternalLink` 图标），有 `sourceUrl` 的文章显示，`target="_blank"` 新标签打开 + `rel="noopener noreferrer"`
- **生词本导入/导出**（`storage.ts` + 生词本页）：
  - 导出：`exportVocabulary()` 序列化全部生词为 JSON，前端 Blob + `URL.createObjectURL` 下载为 `dailyenglish-vocabulary-YYYY-MM-DD.json`
  - 导入：`<input type="file">` 读文件 → `importVocabulary(raw)` 校验 JSON 数组 → 逐条去重合并（按 word），旧格式自动迁移成 FSRS 卡
  - UI：生词本页头"导出 / 导入"按钮 + 导入结果提示（新增 N 个 / 跳过 M 个）
- **词典缓存管理**：`clearDictCache()`；dashboard 加"词典缓存 N 条"显示 + "清理缓存"按钮

## 技术决策及理由

1. **导入用文件而非粘贴**：生词量可能不小，文件选择器体验最好；`FileReader.readAsText` 读取，不需要上传后端（数据本来就在本地）。
2. **导入幂等 + 自动迁移**：按 `word` 去重跳过已有项；旧格式生词（无 `card` 字段）走 `migrateEntry` 重建 FSRS 卡，导入即兼容。
3. **导出 JSON 而不是 CSV**：生词含 FSRS 卡片状态（stability/difficulty/due 等），JSON 无损往返；CSV 适合人看但会丢调度数据。
4. **缓存清理入口放 dashboard**：属于"我的学习"的管理区，和统计放一起语义顺。
