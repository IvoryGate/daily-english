# 阶段 29：推荐冷启动增强

## 背景思考

阶段 28 把首页「为你推荐」接上了词汇画像，但当时的实现有个明显的盲区：

```ts
if (!stats || stats.level.level === 0) return []
```

只有**登录 + 有游戏等级**的用户才能看到「为你推荐」。这导致两类用户首页没有指引：

1. **未登录访客**——他们正在犹豫要不要注册，最需要内容吸引力；
2. **刚注册的新用户**（等级 0）——行为数据为零，却恰恰最需要"从哪篇开始"。

产品直觉是：**冷启动用户是最需要推荐的人**。他们的画像还没建立，但不代表没有"大概率适合"的内容——所有站点的默认档（最容易的文章）就是最好的起点。

## 完成内容

### 「为你推荐」全栈逻辑重构（`frontend/src/pages/ArticleListPage.tsx`）

改成一个统一的、分档的推荐逻辑：

```ts
const level = stats?.level.level ?? 0
const maxLevel = level > 0 ? maxVocabForLevel(level) : 'senior'
const maxIdx = VOCAB_LEVELS.indexOf(maxLevel)
const candidates = articles.filter((a) => {
  const lv = a.vocabLevel
  if (!lv || lv === 'advanced') return false
  const rank = VOCAB_LEVELS.indexOf(lv as VocabLevel)
  if (rank > maxIdx) return false
  // 有等级时贴合画像区间；区间为空时以「≤上限」兜底
  if (level > 0) {
    const range = vocabRangeForLevel(level)
    if (range.includes(lv as VocabLevel)) return true
  }
  return true
})
const unread = candidates.filter((a) => !reading[a.id])
const pick = (unread.length > 0 ? unread : candidates)
  .slice()
  .sort((a, b) => (a.vocabScore ?? 0) - (b.vocabScore ?? 0))
return pick.slice(0, 3)
```

关键点：

- **等级 0 / 未登录 → 入门档**：`maxVocabForLevel(0)` 不存在，直接给 `'senior'` 上限，只推荐最容易的文章，排除超纲。
- **有等级 → 画像区间**：先命中 `vocabRangeForLevel(level)` 的区间；区间没有文章时用「≤上限」兜底（和阶段 28 的容错逻辑一致）。
- **统一排序**：`vocab_score` 升序，让用户先看到最容易的。

### 渲染条件放宽

- `{user && recommended.length > 0}` → `{recommended.length > 0}`：不登录也能看推荐。
- Lv 徽标只在 `stats.level.level > 0` 时显示，未登录/新用户不显示"Lv0"这种尴尬文案。

## 技术决策及理由

1. **冷启动用「入门档」而非「随机/热度」**：没有行为数据时，"全站最容易的文章"是信息增益最高的推荐——它保证任何用户都能读懂，且起到产品教学作用。随机推荐会打击刚来的用户。
2. **不做"未登录单独一套推荐算法"**：冷启动和 Lv0 其实是同一档，一套逻辑覆盖，避免两条代码路径。
