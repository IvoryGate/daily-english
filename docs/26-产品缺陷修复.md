# 阶段 26：产品缺陷修复（正文净化 + 生词分级）

## 背景思考

功能堆得差不多后，我停下来以"真实用户"视角审视这个产品，发现它"很完整"但"不怎么好用"。核心问题不在缺功能，而在**关键链路颗粒度粗糙**：正文带杂质、统计虚高、重点词没逻辑、生词表没规范。这些是让用户"用不下去"的真问题。

于是围绕产品批评拆成两类缺陷：

- **P0（必须修）**：
  - 正文不纯净（抓取的正文夹带"NEXT/媒体占位/CTA/订阅邀请"等杂质段）
  - 统计虚高（"词数起点/增量"凭猜测，阅读容量按分钟×200 假算）
- **P1（规范 + 价值）**：
  - 重点词无规范性（用前端 `extractKeywords` 随便挑词，没有分级依据）
  - 生词没分级（所有词永不分级，不具备"阶段性筛选能力"）
  - 学习路径无逻辑（词汇/复习靠推荐，没有课程或主题阶梯）——本轮做分层读取，P2 再做路径

先修 P0 + P1 前三项，把数据地基打正。

### P1-2 词形归并（lemmatization）

- 用 **nltk + WordNet** 做词形还原（running→run、took→take、children→child、wolves→wolf），再按归并后的原形查词频、分级。
- 依赖已加 `requirements.txt`（`nltk==3.10.2`），语料放项目 `~/nltk_data`。
- 踩坑：nltk 3.10 对含中文（`桌面`）的数据路径触发 `Unauthorized path` 安全校验，需把语料放 `/home/xxx/nltk_data` 这种 ASCII 路径。
- `crawler/lemmatize.py`：先动词还原再名词还原的顺序（小直径覆盖更全）。

### P1-3 后端分级 + 重点词接口（重写）

- `crawler/keywords.py`：`extract_keywords` = WordNet 词形归并 + 词频 + 逐词分级。

## 技术决策及理由

- **分级用真词表而非 AI 判别**：AI 分级不稳定、还要花 tokens；预生成 8 级词表 O(1) 查表，可控、可离线。
- **Lemmatization 用 nltk+WordNet 而非简单词干表**：WordNet 是词根映射最准的现成实现，词形归并质量决定频次和分级是否可靠——这是"生词规范"的生命线，用户坚持不降级。
- **分级定义为"最基础命中级别"**：词只要在初中表里就标初中，A 认知层级，贴合"生词 = 更该学的词"的直觉。
- **词表放 `app/data/` 而非 `backend/data/`**：后者 gitignored，部署即丢；词表是应用静态资源，应当入库随代码发布。

## 实际命令

```bash
# 生成分级词表（需先备好 ECDICT 的 dict_stardard.csv_x 与 mahavivo 专八词表）
cd backend && ./.venv/bin/python scripts/gen_word_lists.py

# 回填净化正文
./.venv/bin/python scripts/clean_articles.py

# 后端启动（测试分级接口）
./.venv/bin/uvicorn app.main:app --port 8000

# 前端构建 / lint
cd frontend && npm run build && npm run lint
```

## 踩坑记录

- `GET /{id}/keywords` 与 `GET /{id}` 冲突：必须把带子路径的路由注册在参数路由之前，否则被接住。
- 词表放在 `backend/data/` 会被 gitignore 忽略 → 部署实例缺词表 → 分级全超纲/为空。移到 `app/data/`。
- nltk 3.10 中文路径安全限制（`桌面` 触发 `Unauthorized path`），语料库塞回 ASCII 的 `~/nltk_data`。
