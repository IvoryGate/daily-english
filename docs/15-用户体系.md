# 阶段 15：用户体系（15.2 数据云端化）

> 15.1 后端认证基础 已见 `docs/15-用户体系.md` 的 15.1 小节（登录注册 + JWT）。
> 本文档随 15.2 更新。

## 背景思考

15.1 完成了账号与认证（注册/登录/JWT），但用户的生词本、收藏、阅读记录还全部存在浏览器 localStorage 里——换设备就没了，而且这些数据没有归属。15.2 的目标是把这三类个人数据搬到后端数据库，按 `user_id` 隔离，为后面前端登录后自动同步做准备。

设计时尽量对齐前端已有的数据结构，避免后面 15.4 做切换时来回改：

- 生词 `VocabEntry` 里的 FSRS 卡片（`card` 字段）是一个嵌套对象，用 JSON 列直接存
- 阅读记录是"一篇文章一条"（upsert 语义），前端 `saveProgress` 是覆盖写
- 收藏是 `number[]`（文章 id 列表）

## 完成内容

**模型（`models.py`）**：新增三张表，全部带 `user_id` 外键（级联删除）：

| 表 | 唯一约束 | 说明 |
|---|---|---|
| `vocabulary_entries` | `(user_id, word)` | 生词：word/phonetic/definition/source_title/added_at/card(JSON) |
| `bookmarks` | `(user_id, article_id)` | 收藏：user_id + article_id + created_at |
| `reading_records` | `(user_id, article_id)` | 阅读：read_at + progress(0~1) |

建表直接复用 `seed()` 里的 `Base.metadata.create_all(engine)`——幂等，已有表不会动，新表自动创建。

**Schema（`schemas.py`）**：`VocabCreate/VocabUpdate/VocabOut`、`BookmarkOut`、`ReadingIn/ReadingOut`、`MeData`（一次拉全量）。注意 `VocabOut`/`BookmarkOut`/`ReadingOut`/`UserOut` 都加了 `from_attributes=True`。

**路由（`api/routes/me.py`，prefix `/api/me`）**：

- `GET /api/me/data`：一次返回 user + 生词 + 收藏 id 列表 + 阅读记录（15.4 前端登录后一次性拉全量用）
- 生词：`GET/POST /api/me/vocabulary`、`PATCH/DELETE /api/me/vocabulary/{word}`
- 收藏：`GET /api/me/bookmarks`、`POST/DELETE /api/me/bookmarks/{article_id}`
- 阅读：`GET /api/me/reading`、`PUT /api/me/reading/{article_id}`（upsert）、`DELETE`

全部走 `get_current_user` 依赖，无 token / 坏 token 一律 401。

## 技术决策及理由

1. **JSON 列存 FSRS 卡片**：card 是 ts-fsrs 的序列化对象，结构固定且小，SQLite 的 JSON 列存进来就是文本，Pydantic `dict` 类型直接映射，最省事。因为每次都整卡覆盖写（PATCH 传整个 card），不需要 SQLAlchemy 的 `MutableDict` 追踪。
2. **阅读记录用 upsert（PUT 幂等）**：前端语义就是"这篇文章读到 50%"覆盖写，天然一篇文章一条；`(user_id, article_id)` 唯一约束兜底。
3. **`/api/me/data` 合集接口**：登录后前端只要发一个请求就能恢复全部个人数据，避免 3 个请求各拉一次（对个人项目意义不大，但 15.4 切换逻辑会简单很多）。
4. **`from_attributes=True` 的三张 schema**：踩了个坑（见下），手动构造嵌套 `MeData` 时 FastAPI 不会自动给嵌套模型开 ORM 转换。

## 踩坑记录

**FastAPI 嵌套响应模型不会自动 from_attributes**。`GET /api/me/data` 直接 500：

```
ValidationError: 1 validation error for MeData
user
  Input should be a valid dictionary or instance of UserOut [type=model_type, input_value=<app.models.User object ...>]
```

原因：FastAPI 只在**最外层** response_model 帮你开 `from_attributes=True`；`MeData` 是我手动 `MeData(user=ORM对象, ...)` 构造的，里面嵌套的 `UserOut`/`VocabOut` 走的是模型自己的配置，没有开 ORM 转换，于是把 ORM 对象当成非法输入。

解决：给 `UserOut`/`VocabOut`/`BookmarkOut`/`ReadingOut` 都显式加 `model_config = ConfigDict(from_attributes=True)`。

**新路由没生效的假警报**：用 `app.routes` 检查路由时只看到 5 条（openapi/docs/health），差点以为 include_router 没生效。实际是这版 FastAPI 把挂载的路由包成 `_IncludedRouter` 惰性展开，`r.path` 是 `None`，被我过滤掉了。**教训：检查路由别用 `r.path` 集合法，直接看总数或 curl 接口。** 重启 uvicorn（非 `--reload` 启动）后接口一切正常。

## 实际命令

```bash
# 登录拿 token
curl -X POST localhost:8000/api/auth/login -H 'Content-Type: application/json' \
  -d '{"email":"tester@example.com","password":"secret123"}'

# 生词 CRUD
curl -X POST localhost:8000/api/me/vocabulary -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' -d '{"word":"harbinger","source_title":"The Atlantic"}'
curl -X PATCH localhost:8000/api/me/vocabulary/harbinger -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' -d '{"card":{...FSRS...}}'
curl -X DELETE localhost:8000/api/me/vocabulary/harbinger -H "Authorization: Bearer $TOKEN"

# 收藏 / 阅读
curl -X POST localhost:8000/api/me/bookmarks/1 -H "Authorization: Bearer $TOKEN"
curl -X PUT localhost:8000/api/me/reading/1 -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' -d '{"progress":0.5}'
curl localhost:8000/api/me/data -H "Authorization: Bearer $TOKEN"
```

验证过的分支：注册→重复 400、登录→me、生词增改删、收藏增删+404、阅读 upsert（改 progress 同一条）、无 token/坏 token 401，全部符合预期。
