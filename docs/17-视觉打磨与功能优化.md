# 阶段 17：视觉打磨 + 功能优化

> 复盘（阶段 16）之后的一轮「面子里子一起做」：先按用户确认的方向做视觉打磨，再顺手补四类功能优化。README 留到本轮结束后再写。

## 一、视觉打磨：温暖的阅读感

### 背景思考

复盘时确认了打磨方向——从「纯黑白灰极简」转向**「温暖的阅读感」**：米白纸感底色、暖墨色文字、弱化边框强调排版。这是阅读类产品的气质，也和项目定位（每天读一篇英文）天然契合。

### 完成内容

1. **设计 tokens 重写（`index.css`）**：
   - 背景 `oklch(0.982 0.006 82)` 米白纸感，前景 `oklch(0.26 0.02 55)` 暖墨黑
   - 主色 `oklch(0.42 0.085 45)` 陶土棕，按钮/链接/高亮统一用它
   - 暗色模式同样走暖调（不是纯黑，是暖褐底）
   - 新增 `--font-reading` 衬线字体栈（Georgia → 宋体兜底），阅读正文专用
   - 圆角从 `0.625rem` 微调到 `0.75rem`，更柔和

2. **阅读页排版**：
   - 正文改衬线字体 + `17px` / `行距1.9`（从 15px/1.75 提上来），段落间距加大
   - 标题也换衬线，`leading-snug` 更贴近纸书标题感
   - 顶部加**阅读进度细条**（随滚动实时更新，陶土色）

3. **全局细节**：
   - ArticleCard：标题衬线 + hover 时边框高亮 + 柔和阴影
   - Logo 从「裸图标」改为「圆角底 + 图标」的品牌块
   - 登录/注册页、空状态页（生词本空/复习空/复习完成）统一品牌图标块
   - 卡片/分割线弱化边框、强调层次

### 技术决策及理由

1. **用 oklch 写色板**：整个色板在 oklch 色彩空间定义，色相/明度/彩度独立可控，暖调的"纸感"比 hex/rgb 更好调。
2. **衬线只给正文**：英文阅读衬线（Georgia）可读性和"书感"远好于无衬线，但 UI 控件保持 Geist 无衬线，避免界面变老气。
3. **进度条用固定定位细条**：不占布局、不抢注意力，纯装饰性反馈。

## 二、功能优化

用户从四个方向里全选了，逐项落地：

### 1. 阅读体验类
- **深色模式**：`lib/theme.ts`（亮/暗/跟随系统三态，localStorage 持久化，`main.tsx` 渲染前初始化防闪烁），header 加切换按钮循环
- **字号调节**：详情页 A-/A+ 四档（sm/md/lg/xl），localStorage 记忆，正文实时换字号
- **朗读全文**：`lib/speech.ts` 的 `startArticleSpeak`（Web Speech API 逐段朗读，自动选英语音色），工具栏朗读/停止按钮
- **阅读进度条**：见视觉部分

### 2. 生词复习类
- **发音朗读**：`speak()` 工具，点词面板、生词本、复习卡背面都有喇叭按钮
- **导出 Anki**：生词本「导出 Anki」按钮，生成 TSV（word / phonetic / definition 三字段，Anki 文本导入格式）
- **乱序复习**：复习页 shuffle 按钮，只打乱剩余队列（已答的不重排）
- **复习统计**：Dashboard 加「待复习」统计卡 + 快捷去复习入口

### 3. 内容类
- **随机一篇**：列表页按钮，从当前可见文章随机挑一篇跳转
- **今日推荐**：列表页顶部推荐卡，按日期做确定性挑选（`dayNumber % length`，每天固定一篇不跳动）

### 4. 体验细节类
- **首页改版**：今日推荐卡片即首页改版核心
- 骨架屏/空状态统一（前述）

## 三、踩坑记录

1. **朗读停止后按钮状态不还原**：`toggleArticleSpeak` 内部同步调 `onEnd()`（内部 `setReadingAloud(false)`）又接着函数式 `setReadingAloud(on => !on)`，React 批处理时两个 setState 叠在一起，`!on` 基于的 `on` 已被 onEnd 改过 → 状态反了。**修复：拆成独立的 `startArticleSpeak` / `stopArticleSpeak`，由组件显式控制状态，不再用返回值+副作用搅在一起。**
2. **CDP 验证 "复习进度 1/3" 却抓到 "tester"**：复习页测试里取"第一个单词"时抓到了 header 里的用户名。**教训：DOM 断言要精确选择器，别用 `body.innerText.split` 猜第一个非空行。**

## 附：词典升级为有道（中文释义 + 真人发音）

### 背景

用户反馈原来的 `dictionaryapi.dev` 词典"不全且全是英文释义"。实测它的定义质量确实差（run 的第一条释义甚至是循环定义 "To run."），对英语学习者不友好。确认后换用**有道词典**：免费、中英释义、带音标、还有美/英真人发音音频。

### 实现

1. **后端代理 `api/routes/dictionary.py`**：
   - `GET /api/dict/{word}` 转发到 `dict.youdao.com/jsonapi`（带 UA 头防 403）
   - 解析 `ec.word[0]`：`trs[].tr[].l.i[]` 是中文释义（每条前面带词性 v./n./adj.），`usphone/ukphone` 是美英音标
   - 发音音频：`usspeech/ukspeech` 字段拼成 `https://dict.youdao.com/dictvoice?audio={word}&type={1英|2美}`（实测可播放 audio/mpeg）
   - 7 天内存缓存 + 查不到返回 404
   - **为什么走后端代理**：有道 jsonapi 不带 CORS 头（浏览器直调被拦 403），但 GET 代理恰好是前后端分离架构该做的事
2. **前端改造**：
   - `DictEntry` 类型改为 `phoneticUs/phoneticUk/audioUs/audioUk` + meanings
   - `dictionary.ts` 从请求外网改成请求 `/api/dict/{word}`
   - WordPanel 显示美英双音标；发音按钮优先播**有道真人音频**（`new Audio(url)`），失败回退 Web Speech；收藏生词时音标取美音

### 踩坑记录

1. **有道 `return-phrase` 不是字符串**：真实结构是 `{"l": {"i": "run"}}` 嵌套对象，`str()` 直接转出来是 `{'l': {'i': 'run'}}`。写了 `_extract_phrase` 递归解包。
2. **旧词典缓存结构不兼容**：dictCache 里存的是旧英英结构，新结构读出来字段对不上。验证时先清了 localStorage，实际老用户会静默重新查词（缓存命中判断只看 word key，结构对不上时当无缓存处理即可，无需迁移）。

### 验证

- 后端 curl：`/api/dict/run` 返回中文释义 + 美英音标 + 音频 URL；`zxqzzx` 404
- CDP 点词："making" 面板显示中文释义（制作，生产/素质，潜在能力…）+ 美英音标（美 ˈmeɪkɪŋ 英 ˈmeɪkɪŋ）；发音按钮点击无 JS 报错
