# 阶段 23：文章配图（真实图 + 渐变兜底）

> 用户反馈：杂志式布局"还是差点意思，应该是没有图片的缘故"。确认方案：**抓真实文章图**（og:image）。

## 一、问题

文章表没有图片字段，正文里也没有可靠图片 URL。纯文字卡片没有视觉锚点，杂志感出不来。

## 二、数据层

- **Article 加 `image_url` 列**（String 800）+ `migrate()` 补列 + `schemas.ArticleSummary` 加字段
- **爬虫增强**（三个 provider）：
  - `base.py` 加通用 `extract_og_image()`——优先 `meta[property="og:image"]`，其次 `twitter:image`，兜底正文第一张图
  - VOA / Guardian / Atlantic 三个 provider 抓文章时提取图片存入 `RawArticle.image_url`
  - `run.py` 入库时写入
- **回填脚本 `scripts/backfill_images.py`**：给已有 44 篇逐个抓源页取 og:image（幂等、限速、单个失败不中断）

**回填结果**：40 篇拿到真实配图（VOA `gdb.voanews.com`、卫报 `i.guim.co.uk`、大西洋 `cdn.theatlantic.com`），4 篇无图（内置 seed 文章无 source_url）。三源图片全部验证可访问（200 image/jpeg）。

## 三、前端

- **`ArticleThumb` 组件**：有图显示 `<img>`（加载失败自动隐藏露出兜底），无图显示标题首字母 + 渐变背景（按 id 确定性配色）
- **ArticleCard**：顶部加 `aspect-[16/9]` 配图，收藏按钮加半透明底
- **HERO 主推**：改图片在上（h-64/md:h-80，hover 缩放）+ 文字在下的大卡

## 四、踩坑记录

1. **API 没返回 image_url**：`articles.py` 的 `_to_summary()` 手动构造 schema 时漏传了 `image_url`——数据库有值但接口不返回。修 `_to_summary` 补上。**教训：加列后要检查所有手动构造 schema 的地方。**
2. **图片跨域**：外部图用 `<img>` 直接引用不受同源限制（img 标签无 CORS 约束），无需代理。

## 五、验证（CDP）

- API：44 篇中 40 篇有 image_url
- 首页 13 个文章链接中 11 张图渲染成功（1200px 主推图正常加载），4 篇 seed 无图走渐变兜底
- 主推 HERO 图 hover 缩放、卡片图加载正常
- build/lint 通过
