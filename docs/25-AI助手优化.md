# 阶段 25：AI 助手三优化（流式性能 / Markdown / 侧边抽屉）

> 用户反馈三个问题：① AI 悬浮窗游离在体系外、质感廉价；② AI 输出 Markdown 未渲染；③ 调用比 opencode 慢。先调查再解决。

## 一、性能瓶颈定位（核心）

### 根因

`backend/app/ai/chat.py` 的 `_stream_one_round` **把流式增量全部收集到列表，等流完全结束后才 yield 一次完整文本**。前端要等整个生成完成才看到内容，完全丧失了流式体验。

**实测**：第一字节延迟 6411ms（6.4 秒）——等于整个生成时长。

### 对比 opencode 为什么快

opencode 是**逐 token 转发**，第一字几百 ms 出现。我们的实现攒完才发。

### 修复

- `_stream_one_round`（攒完才发）→ 新 `_stream_forward`（**边读边 yield**，第一个 token 立即推送）
- 纯文本内容实时转发；工具调用（tool calling）仍需完整收集，但工具执行结果即时回填
- `run_chat` 流式路径改用 `_stream_forward`

### 剩余延迟分析

修复后第一字节仍有 3.5~8s 波动——这是 **Zen 免费模型服务端固有**（deepseek/mimo 等推理模型先输出 reasoning 再出 content）。实测各模型首 token：**mimo(3.5s) < nemotron(5.5s) < north(5.8s) < deepseek(7.6s) < ling(8.2s)**。已将默认模型从 deepseek-v4-flash-free 换成最快的 **mimo-v2.5-free**。

## 二、Markdown 渲染

- 安装 `react-markdown`（无额外依赖）
- AI 消息用 `<ReactMarkdown>` 渲染，用户消息保持纯文本
- `index.css` 加 `.ai-markdown` 样式：粗体/列表/标题/代码块/引用适配现有主题

## 三、侧边抽屉形态

- 悬浮按钮：纯图标圆球 → **"AI 助手"文字标签**按钮（更贴合站内）
- 面板：右下角悬浮窗 → **右侧全高抽屉**（`w-[400px]` + 遮罩 + 点击外部关闭），更像站内功能而非外挂
