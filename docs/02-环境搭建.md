> 本文档是「阶段 02 环境搭建」的详细开发记录，口语化、为博客积累素材。

## 1. 背景：这一步到底要干什么

规划阶段（01）定完方向后，就该让代码跑起来了。这一步的目标很简单：

1. 本机环境确认（Node、Python、包管理）
2. 前端骨架：用官方脚手架初始化一个 Vite + React + TypeScript 项目
3. 后端骨架：Python 虚拟环境 + FastAPI 最小应用，能访问到一个健康检查接口
4. 落地 Git 规范（.gitignore 等），保证以后提交不会把 node_modules、venv 这种垃圾提交上去

这一阶段**不写业务代码**，只求"空壳能跑"。先把地基打稳，后面所有阶段的 bug 排查都会轻松很多。

## 2. 环境检查：一开始就发现两个坑

先盘了一下本机环境：

```
Node    v22.23.1  ✅
npm     10.9.8    ✅
Python  3.10.12   ✅
git     2.34.1    ✅
pip     无        ❌
pnpm/uv 无        （不需要）
```

Node 和 npm 都很新（Node 22），Python 是 3.10（有点旧，但 FastAPI 完全支持）。git 正常。

**坑 1：python 没有 pip。** `python3 -m pip` 直接报"No module named pip"。查了一下这是 Debian/Ubuntu 系统的经典问题：系统自带的 Python 默认不带 pip，需要单独装 `python3-pip` 和 `python3-venv`。

**坑 2：没有 sudo 权限。** 尝试 `sudo apt install python3-venv` 时发现 sudo 需要密码，而我无法交互输入。也就是说系统级装包这条路走不通。

### 破解办法：纯用户空间的 virtualenv

既然系统装不了 venv 模块，就绕开它：

```bash
# 1. 用官方脚本把 pip 装到用户目录（不需要 sudo）
curl -sS https://bootstrap.pypa.io/get-pip.py -o /tmp/get-pip.py
python3 /tmp/get-pip.py --user

# 2. 用 pip 装 virtualenv（也是个纯用户空间的东西）
python3 -m pip install --user virtualenv

# 3. 用 virtualenv 创建项目虚拟环境（绕过了系统缺失的 venv 模块）
mkdir -p backend
python3 -m virtualenv backend/.venv
```

`virtualenv` 是 `venv` 的老牌替代品，自带 pip，不用依赖系统 ensurepip。这样既不用 sudo，又拿到了干净的隔离环境。**这是本阶段最大的一个坑，也是最有价值的一条经验**。

## 3. 后端依赖安装：慢到怀疑人生

venv 建好后装依赖：

```bash
cd backend
./.venv/bin/pip install fastapi "uvicorn[standard]" sqlalchemy
```

**坑 3：慢。** 装了几分钟还没完，一度以为卡死。原因有二：

1. 项目在 Windows 挂载盘 `/mnt/f/` 上，WSL 跨文件系统读写慢，pip 解包、写文件都被拖累；
2. pip 默认直连 PyPI 官方源，国内网络访问慢。

**解决：换清华镜像。**

```bash
./.venv/bin/pip install -i https://pypi.tuna.tsinghua.edu.cn/simple fastapi "uvicorn[standard]" sqlalchemy
```

> 教训：国内环境 pip 装包，第一件事就是 `-i https://pypi.tuna.tsinghua.edu.cn/simple`。npm 装包同理可以用 `--registry=https://registry.npmmirror.com`。

装完的核心版本（记一下，以后 troubleshooting 有用）：

```
fastapi      0.141.1
SQLAlchemy   2.0.51
uvicorn      0.52.1
```

## 4. 后端最小骨架

按规划文档的目录结构，先建最小可运行的骨架：

```
backend/
├── requirements.txt       # 依赖锁定
├── .venv/                 # 虚拟环境（gitignore）
└── app/
    └── main.py            # FastAPI 入口
```

`requirements.txt` 只放三个核心依赖（版本号锁死，保证可复现）：

```
fastapi==0.141.1
uvicorn[standard]==0.52.1
sqlalchemy==2.0.51
```

`app/main.py` 是最小 FastAPI 应用：

```python
from fastapi import FastAPI

app = FastAPI(title="DailyEnglish API", version="0.1.0")


@app.get("/api/health")
def health() -> dict:
    return {"status": "ok"}
```

启动并验证：

```bash
./.venv/bin/uvicorn app.main:app --port 8000
curl http://127.0.0.1:8000/api/health
# → {"status":"ok"}  ✅
```

健康检查通了，后端空壳完成。

### 坑 4：验证接口时的诡异现象

验证过程中连续踩了几个小坑，值得单独记录：

1. **后台进程 + curl 的时序**：在一条命令里 `uvicorn &` 然后立刻 `curl`，会连不上——因为 `/mnt/f` 上首次启动 FastAPI 要导入一堆包，慢，curl 跑太快。**解决**：curl 加个重试循环，等服务器真正就绪。
2. **pkill -f 自杀**：用 `pkill -f "uvicorn app.main"` 清理后台进程时，把正在执行命令的 shell 也杀了——因为 bash 的命令行里也含这个字符串，`-f` 是按整个命令行匹配的。**解决**：用 `pkill -f "[u]vicorn"`，字符类 `[u]` 让正则匹配不到自身命令行。这个小技巧很实用。
3. **后台进程占管道**：`uvicorn ... &` 直接后台跑，会占住终端输出管道，导致工具一直等它退出。**解决**：`setsid ... </dev/null >/tmp/uvicorn.log 2>&1 &`，完全脱离会话再后台。

## 5. 前端骨架：Vite 官方模板

后端能跑了，前端也整上：

```bash
npm create vite@latest frontend -- --template react-ts
cd frontend && npm install
```

生成的是 Vite 8.2（Rolldown 版）模板，直接附带了 React 19.2、TypeScript 6.0、oxlint。注意几个新点：

- **lint 命令是 `oxlint` 而不是 eslint**（新模板默认用 oxlint，规则引擎，更快）
- build 命令是 `tsc -b && vite build`（先 TypeScript 类型检查再打包）
- 自带 `frontend/.gitignore`

验证：

```bash
cd frontend
npm run build   # tsc 类型检查 + 打包 → 786ms 通过 ✅
npm run lint    # oxlint → 0 warnings 0 errors ✅
```

模板生成的 `package.json` scripts：

```
dev       → vite          # 开发服务器（端口 5173）
build     → tsc -b && vite build
lint      → oxlint
preview   → vite preview
```

## 6. Git 规范落地

写根目录 `.gitignore`，统一兜底（`frontend/.gitignore` 已覆盖前端的 node_modules/dist）：

```
# Python / backend
__pycache__/
*.py[cod]
.venv/
backend/data/
*.db
*.sqlite3

# Node
node_modules/
dist/

# 编辑器
.vscode/
.idea/
*.sw?
.DS_Store
```

以后 SQLite 数据库文件放 `backend/data/`，不提交；虚拟环境、依赖目录统统不提交。
