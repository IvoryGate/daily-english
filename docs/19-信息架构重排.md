# 阶段 19：信息架构重排（单站分路由 + 个人中心整合 + Dashboard 拆组件）

> 用户反馈：UI 设计不太合理、有些混乱、样式简陋。先做**信息架构重排**（治"混乱"的根），视觉精细化留到下一轮。同时确认架构：**单站分路由**，不拆两个独立部署。

## 一、问题诊断

原架构的混乱根源：**9 个页面全挤在一根横向导航里，没有信息分层**。

```
旧导航（8 项一锅烩）：文章 | 我的学习 | 生词本 | 复习 | [主题] | 添加文章 | 用户名 | 退出
```

具体问题：
1. **没有主次**。学习工具（生词本/复习）和内容入口（文章）平级，低频操作（添加文章）占显眼位置。
2. **Dashboard 是重灾区**：633 行一个文件，塞了等级卡/streak/今日目标/6 张统计卡/多个提示条/热力图/词汇曲线/复习趋势/成就墙/最近阅读/缓存清理/按钮区——本质是"个人后台"，却和站点内容混在一页。
3. **职责边界模糊**：添加文章（个人内容）和文章列表（公共内容）混在一个体系。

## 二、架构决策：单站分路由

| 方案 | 结论 |
|---|---|
| 独立站点（两个域名/部署） | ✗ 本项目后台是个人中心不是运营后台，不值得拆两套构建/登录态 |
| **单站分路由**（前台 `/` + 个人中心 `/account/*`） | ✅ 同一构建同一登录态，但导航/布局清晰分层 |

**路由域划分：**
- **前台**（登录与否都可用，保持阅读气质）：`/` 文章列表、`/articles/:id` 阅读、`/login` `/register`
- **个人中心**（受保护 + 二级导航）：`/account/dashboard|vocabulary|review|settings|new`
- **旧路径全部重定向**：`/dashboard` → `/account/dashboard` 等

## 三、完成内容

1. **SiteHeader 精简**：只留 `文章`（前台）+ `个人中心`（登录时）+ 主题 + 登录态。导航从 8 项降到 3-4 项。
2. **AccountLayout**（新组件）：受保护的布局路由，提供二级导航标签（我的学习/生词本/复习/设置/添加文章），`<Outlet />` 承载子页面。
3. **App.tsx 路由重构**：嵌套路由 `Route path="/account" element={<AccountPage/>}>` + 6 个旧路径重定向。
4. **Dashboard 拆组件**：633 → 516 行，图表组件（Heatmap/LineChart/BarChart）抽到 `components/account/charts.tsx`（130 行）。
5. **内部链接全部改 `to="/account/xxx"`**。

## 四、技术决策及理由

1. **AccountLayout 用嵌套路由 + Outlet**：个人中心各页共享顶部二级导航，切页不重载导航、URL 语义清晰（`/account/review` 一眼知道在哪）。
2. **旧路径重定向而不是删除**：旧书签/分享链接不 404，且验证逻辑只需一个文件。
3. **Dashboard 只抽图表组件**：本轮目标是"治混乱"，把最独立的图表类抽出去足够；StatCard/ProgressBar 等小内联组件留在页面内避免过度拆分。

## 五、验证（CDP 全链路）

- 未登录 header：`DailyEnglish | 文章 | 登录`
- 未登录访问 `/account/*` 或旧 `/dashboard` → 重定向 `/login`
- 登录后 header：`DailyEnglish | 文章 | 个人中心 | 退出`
- `/account` → 自动跳 `/account/dashboard`
- 个人中心二级导航 5 项齐全，生词本/复习/设置页正常
- 旧路径 `/vocabulary` `/review` 登录后 → `/account/xxx`
- Dashboard 词汇量增长 + 复习趋势两个 SVG 图表正常
